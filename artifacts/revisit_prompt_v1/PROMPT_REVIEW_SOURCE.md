## 4. 关键决策为何这样安排

**先冻结E1做提示适配**：既保留当前最强已发布感知资产，又把本轮差异集中于提示进入感知的方式。在未取得新增GPU预算的情况下，不把旧1,800GPUh当成新额度。代价是本轮不能代表全模型充分训练后的性能上界。

**保留M0–M3强对照，再分M4/M5/M6**：普通query传播、已有post-proposal read和额外参数本身都可能贡献收益。将检索结构、检索监督和拒绝评分分开，是为了让结果具有解释力，而不是增加名字相近的模块。

**有限数值排查加明确条件性探索**：历史报告已揭示新进程浮点非重复。新指令没有宣布问题消失，也不要求无限CUDA审计；结构错误必须停，浮点波动只有在完整固定CAL面板的预设范围内才允许继续，并在最终报告保留未知根因。

**不把此次协议等同完整CVPR证据包**：已有面板存在历史暴露，父模型只有一个训练种子。本轮的终点是完整执行、可信选模及GitHub交付；正结果支持下一步投入，负结果同样应该发布。
