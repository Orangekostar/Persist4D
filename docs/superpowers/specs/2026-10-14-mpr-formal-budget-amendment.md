# MPR 正式训练预算修订

2026-10-14 用户明确指示：“什么预算规则导致的，如果你认为训练有意义就直接启动训练”。该指示授权主执行者调整妨碍正式训练的旧额度，并直接执行已有实验方案。

旧提示词 §11.3 要求从 78 GPU 小时中先预留完整评测、复验和其他阶段成本。真实试跑估计使正式训练余额只剩 4.621675 GPU 小时，而六个变体各 400 步及两个最贵变体复验的保守估计为 20.071986 GPU 小时。原 BLOCKED 锁和已发布结果仍作为原协议结果保存。

本次使用独立分支、工作区和运行目录。新运行池上限设为 100 GPU 小时；原累计 1713.883055 GPU 小时加上此前 MPR 实测 0.931007 GPU 小时，共 1714.814061 GPU 小时，全部计入新运行的历史消耗。累计上限修订为 1823 GPU 小时，保留 8 GPU 小时，故新池与累计限制同时成立。这是有界的预算修订，不是无限训练授权。

沿用原成本公式、完整评测人口和条件复验规则。新锁选择 N=400，评测点 100/200/300/400；新正式训练分配 23.237059 GPU 小时。P0/P1 已有真实证据按来源与哈希记录继承，仅预算核算代码改变；模型、损失、数据、训练器、评测器和选模代码保持原样。新运行重新执行 M0 的三次完整 CAL，以避免混合不同 source identity 的评测行。

六个变体均从冻结 E1-23760 seed45 父模型和 seed146 新模块初始化，不加载试跑权重。每个更新固定 H2/H3/H4/H5 四个 episode，共 14 次阶段前向，400 步不是 400 个场景。单 GPU 顺序执行，保留原 FP32、采样和 RNG 规则。先完成六个正式训练，再执行完整 CAL 和原锁定的选模、条件 seed147 复验、SEL/PB 与机制/资源测试。

运行控制器使用独立进程锁和原收费 child 管理器。每个实际/失败尝试都计费，沿用至多两次重启及相同错误重复停止规则；异常根因和最终科研判断由主执行者负责。后台控制器持续运行，不依赖聊天回合存活；自动流程不发布结果或宣称 CVPR 就绪。

验证：新增预算扩展回归测试和原 T09 核算测试；核验数值来源仅预算文件改变；记录实际启动 PID、GPU、真实优化步与日志。新锁和正式模型产生后不修改其来源哈希。
